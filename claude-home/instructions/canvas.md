## Canvas: drawing Obsidian `.canvas` files

### Essentials

- Every block shows its whole text without scrolling; label blocks are exactly as wide as their longest line.
- Inline code for literal names (fields, tables, enum values, permissions, cardinality); code blocks only for real code.
- A line never crosses or touches a block; it runs only through empty space.
- Lines are straight: blocks sit on a grid, turns go through 10 x 10 empty blocks, text never goes on a line.
- Before finishing: `py ~/home/agents/agent-workflow/second-brain-obsidian/canvas-check.py <file>` reports 0 problems.

Applies to every `.canvas` file an agent creates or edits, in every approach.

### 1. Block size: no scrolling

A block is at least as tall as its rendered text. Estimates at zoom 1:

| Part | Size |
|---|---|
| `##` heading line | 48 px |
| Body line | 26 px |
| Content padding | 28 px vertical, 48 px horizontal |
| Body glyph | 8.4 px, inline code 9.4 px, heading 13.5 px |

A line wider than the block wraps and counts as several lines. Entity blocks
share one width per diagram (300 px is a good default). A label block is as
wide as its longest line plus the padding, with no extra margin.

### 2. Text formatting

- Inline code (`` ` ``) for literal names: field names, table names, enum
  values, permissions, cardinality such as `` `1 - *` ``.
- A code block only for real multi-line code or config.
- Descriptions stay plain text. One fact per line; short lines.

### 3. Lines run through empty space

- A line never passes over, under or along a block other than the two blocks
  it connects, and keeps at least 12 px of clearance from every other block.
- Group borders are not blocks: lines may cross them. A block is either fully
  inside a group or fully outside it.
- Lines do not cross other lines where a different layout avoids it.

### 4. Straight lines, text in blocks

Obsidian draws a line from the middle of one block side to the middle of the
other block side. The line is straight only when the two sides face each other
and line up: right to left at the same center `y`, or bottom to top at the
same center `x`.

- **Grid**: blocks in one row share one center `y`; blocks in one column share
  one center `x`.
- **Turns**: a line turns through an empty 10 x 10 text block placed at the
  corner. One relation becomes a chain of straight segments.
- **Labels**: a line never has a `label`. The text goes into a small label block
  placed on the line, which splits the line into two collinear segments.
- **Branches**: a block with more relations than free sides gets one line to a
  branch block (an empty 10 x 10 block, or a shared label block when all
  branches carry the same text), and the branches start there.
- **Arrows**: only the last segment of a relation has an arrowhead; segments
  that end in a turn, label or branch block have `"toEnd": "none"`.

### 5. Spacing

- The gap between two columns is the widest label block placed in that gap
  plus 24 px on each side, and at least 100 px.
- The gap between rows is 110 px; between two groups 200 px.
- Groups get 40 px of padding around their members.

### Building and checking

A canvas with more than a few blocks is generated by a script, not placed by
hand: entities on grid cells, rows sized by their tallest block, label and turn
blocks computed from the grid. The script is a scratch file and stays out of
the knowledge base.

`second-brain-obsidian/canvas-check.py` in the `agent-workflow` repo checks
rules 1, 3 and 4 (scrolling, lines over blocks, curved lines, labels on lines,
overlapping blocks). Its size estimates are approximate: a block that still
scrolls in Obsidian means the constants need adjusting.
